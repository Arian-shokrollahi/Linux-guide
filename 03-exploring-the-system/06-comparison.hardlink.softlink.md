# راهنمای جامع تفاوت Hard Link و Soft Link در لینوکس

این مستند یک مرجع سریع و کاربردی برای درک تفاوت‌ها، رفتار و کاربردهای **Hard Link** و **Soft Link (Symbolic Link)** در سیستم‌عامل لینوکس است.

---

## 📌 مقدمه و مفاهیم پایه

در سیستم‌فایل‌های لینوکس (مثل ext4)، هر فایل از ۳ بخش اصلی تشکیل شده است:
1. **نام فایل (Filename):** برچسبی که کاربر می‌بیند و به یک Inode متصل است.
2. **اینود (Inode):** شناسه اصلی فایل که متادیتا (حجم، مالک، دسترسی‌ها، زمان‌ها و آدرس بلوک‌های دیسک) را نگه می‌دارد.
3. **بلوک‌های داده (Data Blocks):** محتوای واقعی ذخیره‌شده روی هارد دیسک.

---

## ⚖️ جدول مقایسه کامل

| ویژگی | Soft Link (Symlink) | Hard Link |
|---|---|---|
| **شماره Inode** | اینود جداگانه و جدید دریافت می‌کند | دقیقاً همان Inode فایل اصلی را به اشتراک می‌گذارد |
| **سینتکس دستور** | `ln -s <target> <link_name>` | `ln <target> <link_name>` |
| **پشتیبانی از دایرکتوری (پوشه)** | ✅ بله (می‌توان برای پوشه‌ها ساخت) | ❌ خیر (برای جلوگیری از حلقه‌های بی‌پایان مجاز نیست) |
| **عبور از پارتیشن / فایل‌سیستم دیگر** | ✅ بله (چون فقط آدرس متنی ذخیره می‌کند) | ❌ خیر (باید روی همان پارتیشن باشد) |
| **رفتار پس از حذف فایل اصلی** | ❌ تبدیل به لینک خراب (**Broken Link**) می‌شود | ✅ محتوا تا زمان حذف آخرین هاردلینک سالم می‌ماند |
| **حجم فایل** | برابر با تعداد کاراکترهای مسیر مقصد (چند بایت) | برابر با حجم واقعی فایل اصلی |
| **معادل در ویندوز** | Shortcut (`.lnk`) | Hard Link (`fsutil hardlink`) |

## 🛠️ دستورات ترمینال و مثال‌های عملی

### ۱. ایجاد لینک‌ها
```bash
# ایجاد یک فایل تستی
echo "Hello Linux" > original.txt

# ساخت Soft Link (سافت‌لینک)
ln -s original.txt soft_link.txt

# ساخت Hard Link (هاردلینک)
ln original.txt hard_link.txt
```
---
۲. بررسی ساختار Inode با دستور ls -li
```bash
$ ls -li
1054231 -rw-r--r-- 2 user group 12 Apr 10 12:00 original.txt
1054231 -rw-r--r-- 2 user group 12 Apr 10 12:00 hard_link.txt
1054232 lrwxrwxrwx 1 user group 12 Apr 10 12:01 soft_link.txt -> original.txt
```
تحلیل خروجی بالا:

فایل‌های original.txt و hard_link.txt شماره اینود یکسان دارند (1054231).
شمارنده لینک (ستون سوم) برای آن‌ها برابر با 2 شده است.
فایل soft_link.txt یک اینود کاملاً جدید (1054232) دارد و در بخش دسترسی‌ها با حرف l شروع شده است.

---
دیاگرام نحوه ذخیره‌سازی و رفتار در زمان حذف
```bash
[original.txt]  ──┐
├─► [Inode: 1054231] ──► [بلوک‌های داده: "Hello Linux"]
[hard_link.txt] ──┘

[soft_link.txt] (Inode: 1054232) ──(متن آدرس: original.txt)
```
اگر فایل اصلی (original.txt) حذف شود:

Hard Link: فایل hard_link.txt بدون هیچ مشکلی به کار خود ادامه می‌دهد و اطلاعات کاملاً سالم می‌ماند. تعداد ارجاعات اینود از ۲ به ۱ کاهش می‌یابد و تا زمانی که آخرین هاردلینک حذف نشود، فضا آزاد نمی‌شود.
Soft Link: فایل soft_link.txt خراب (Broken / Dangling) می‌شود؛ زیرا مسیری که به آن اشاره می‌کرد دیگر وجود خارجی ندارد.

---
کاربردهای رایج در دنیای واقعی
کاربردهای Soft Link:

مدیریت کانفیگ وب‌سرورها (مثلاً فعال‌سازی سایت در Nginx با لینک زدن از sites-available به sites-enabled).
ارجاع به نسخه‌های مختلف برنامه‌ها (مثلاً اشاره /usr/bin/python3 به /usr/bin/python3.12).
سازمان‌دهی فایلهای Dotfiles گیت در پوشه ~/.config/.
کاربردهای Hard Link:

سیستم‌های بکاپ‌گیری و Snapshot (صرفه‌جویی در فضای دیسک بدون تکرار داده‌ها).
جلوگیری از پاک شدن تصادفی فایل‌های مهم سیستمی با تغییر نام یا حذف یک فایل.
