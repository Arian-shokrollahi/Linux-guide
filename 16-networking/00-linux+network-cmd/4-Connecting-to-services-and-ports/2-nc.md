ا-`nc` یا **Netcat** یکی از مهم‌ترین ابزارهای Network در لینوکس است. اگر `curl` بیشتر برای **HTTP/API** است، `nc` ابزار عمومی‌تری برای **TCP/UDP، Port و Connection** است.

# ا-`nc` چیست؟

ا-`nc` مخفف **Netcat** است و برای ایجاد و آزمایش ارتباطات شبکه استفاده می‌شود.

به زبان ساده:

```
nc = ابزار ساده برای صحبت کردن با Portهای شبکه
```

مثلاً:

```
nc -vz 192.168.1.10 22
```

یعنی:

> آیا می‌توانم به Port `22` روی این IP وصل شوم؟

---

# ساختار کلی

```
nc [OPTIONS] HOST PORT
```

مثلاً:

```
nc 192.168.1.10 80
```

---

# 1. تست باز بودن یک Port — مهم‌ترین کاربرد

```
nc -zv 192.168.1.10 22
```

گزینه‌ها:

```
-z → فقط Scan/Check کن، داده ارسال نکن
-v → اطلاعات بیشتر نمایش بده
```

اگر Port باز باشد، معمولاً چیزی شبیه:

```
Connection to 192.168.1.10 22 port [tcp/ssh] succeeded!
```

اگر بسته باشد، Connection برقرار نمی‌شود.

### کاربرد واقعی

مثلاً Server داری:

```
192.168.1.100
```

و می‌خواهی ببینی SSH قابل دسترس است:

```
nc -zv 192.168.1.100 22
```

یا Web:

```
nc -zv example.com 443
```

---

# 2. بررسی چند Port

می‌توانی چند Port را هم بررسی کنی:

```
nc -zv example.com 80 443 22
```

یا یک Range:

```
nc -zv example.com 20-100
```

مثلاً برای Troubleshooting می‌توانی بررسی کنی:

```
22  → SSH
80  → HTTP
443 → HTTPS
```

---

# 3. اتصال مستقیم به یک Port

بدون `-z`:

```
nc example.com 80
```

حالا یک Connection واقعی به Port 80 برقرار کرده‌ای.

می‌توانی مثلاً یک درخواست HTTP ساده بفرستی:

```
GET / HTTP/1.1
Host: example.com
```

و Server پاسخ HTTP می‌دهد.

این مثال خیلی خوب نشان می‌دهد که:

```
nc
 ↓
TCP Connection
 ↓
Port 80
 ↓
HTTP
```

در واقع `nc` خودش HTTP Client تخصصی نیست؛ فقط Connection را در اختیارت می‌گذارد.

---

# 4. ا-Netcat به عنوان Server

این یکی از قابلیت‌های معروف `nc` است.

روی یک سیستم:

```
nc -l 1234
```

یعنی:

> روی Port `1234` منتظر Connection باش.

ا-`-l` یعنی:

```
listen
```

حالا از سیستم دیگری:

```
nc 192.168.1.100 1234
```

هر چیزی در یک طرف تایپ کنی، می‌تواند در طرف دیگر نمایش داده شود.

مثلاً:

```
Client                    Server

hello       ---------->   hello
world       ---------->   world
```

برای یادگیری مفهوم **Client/Server و TCP Connection** فوق‌العاده است.

---

# 5. تست ساده شبکه بین دو سیستم

فرض کن دو Linux Machine داری.

روی Server:

```
nc -l 5000
```

روی Client:

```
nc 192.168.1.100 5000
```

بعد:

```
Client → hello
Server → hello
```

اگر ارتباط برقرار شد، می‌دانی که حداقل مسیر شبکه و آن Port قابل دسترسی است.

---

# 6. استفاده از UDP

به صورت پیش‌فرض `nc` معمولاً با TCP کار می‌کند.

برای UDP:

```
nc -u 192.168.1.100 5000
```

و برای Listen:

```
nc -u -l 5000
```

گزینه:

```
-u → UDP
```

پس:

```
TCP → nc
UDP → nc -u
```

---

# 7. ا-Timeout

برای جلوگیری از اینکه Connection مدت زیادی منتظر بماند:

```
nc -zv -w 3 example.com 443
```

ا-`-w 3` یعنی Timeout حدوداً ۳ ثانیه.

برای Script و Troubleshooting کاربردی است.

---

# 8. تست Port روی localhost

خیلی وقت‌ها می‌خواهی ببینی یک سرویس روی سیستم خودت Listening است یا نه:

```
nc -zv localhost 8080
```

مثلاً اگر یک برنامه روی Port `8080` اجرا شده باشد، می‌توانی با این دستور بررسی کنی که Port قابل اتصال است.

---

# 9. بررسی چند Port معروف

مثلاً:

```
nc -zv localhost 22
nc -zv localhost 80
nc -zv localhost 443
nc -zv localhost 3306
```

به این ترتیب می‌توانی ببینی سرویس‌های مختلف قابل دسترسی هستند یا نه.

---

# مهم‌ترین Optionهای `nc`

|Option|کاربرد|
|---|---|
|`-z`|فقط Port را Check کن|
|`-v`|نمایش جزئیات|
|`-l`|Listen|
|`-u`|UDP|
|`-w`|Timeout|
|`-n`|بدون DNS Resolution|
|`-p`|تعیین Local Port در پیاده‌سازی‌هایی که پشتیبانی می‌کنند|

> توجه: بعضی سیستم‌ها از **OpenBSD netcat** و بعضی از نسخه‌های دیگر `nc` استفاده می‌کنند، بنابراین بعضی Optionها ممکن است بین نسخه‌ها متفاوت باشند.

# ۵ کاربرد واقعی `nc`

### 1. بررسی Port

```
nc -zv 192.168.1.10 22
```

**کاربرد:** آیا SSH قابل دسترسی است؟

---

### 2. بررسی HTTPS

```
nc -zv example.com 443
```

**کاربرد:** آیا Port مربوط به HTTPS قابل دسترسی است؟

---

### 3. تست Client/Server

ا-Server:

```
nc -l 5000
```

ا-Client:

```
nc SERVER_IP 5000
```

**کاربرد:** تست ساده ارتباط بین دو سیستم.

---

### 4. تست UDP

ا-Server:

```
nc -u -l 5000
```

ا-Client:

```
nc -u SERVER_IP 5000
```

**کاربرد:** آزمایش ارتباط UDP.

---

### 5. بررسی سرویس روی localhost

```
nc -zv localhost 8080
```

**کاربرد:** فهمیدن اینکه یک Application واقعاً روی Port موردنظر Listening است یا نه.

# تفاوت `nc` و `curl`

این قسمت خیلی مهم است:

|`nc`|`curl`|
|---|---|
|ابزار عمومی Network|ابزار Client برای URL|
|TCP/UDP|عمدتاً HTTP/HTTPS و پروتکل‌های پشتیبانی‌شده|
|تست Port|تست Web/API|
|Listen می‌تواند بکند|معمولاً Client است|
|Connection خام|HTTP را راحت مدیریت می‌کند|

مثلاً:

```
nc -zv example.com 443
```

می‌گوید:

> آیا می‌توانم به Port 443 وصل شوم؟

ولی:

```
curl -I https://example.com
```

می‌گوید:

> آیا Web Server روی HTTPS درست پاسخ می‌دهد؟

این دو **یک کار انجام نمی‌دهند**.

## جمع‌بندی خیلی کوتاه

```
nc
│
├── -z  → Port Check
├── -v  → Verbose
├── -l  → Listen
├── -u  → UDP
└── -w  → Timeout
```

و مهم‌ترین چیزی که باید در ذهنت بماند:

> **`nc` = ابزار ساده برای ساخت، تست و عیب‌یابی Connectionهای TCP/UDP و بررسی Portها.**

برای مسیر Network که داری می‌خوانی، بعد از `nc`، یادگیری **`ss`** خیلی مهم است؛ چون `nc` به تو می‌گوید _«می‌توانم به این Port وصل شوم؟»_ و `ss` کمک می‌کند بفهمی _«روی خود سیستم چه Connectionها و Portهایی در حال Listening هستند؟»_.
