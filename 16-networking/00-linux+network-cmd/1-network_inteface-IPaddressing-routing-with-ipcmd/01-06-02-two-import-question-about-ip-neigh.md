# دو سوال مهم درمورد ip neigh
1. به چه دلیل MAC address نیازه و ip neigh چیکارست؟
2. ایا اتصال فیزیکی هم باشد mac نیازه 
---
## جواب سوال 1:
## چرا MAC لازم است؟

فرض کن کامپیوترت این IP را دارد:

```
PC
IP: 192.168.1.10
MAC: AA:AA:AA:AA:AA:AA
```

و می‌خواهی به این IP پیام بفرستی:

```
192.168.1.20
```

Linux در ابتدا فقط این را می‌داند:

```
Destination IP = 192.168.1.20
```

ولی Ethernet Frame با **MAC Address** کار می‌کند، نه IP.

پس باید بداند:

```
192.168.1.20
       ↓
MAC چیست؟
       ↓
BB:BB:BB:BB:BB:BB
```

بعد Frame ساخته می‌شود:

```
┌─────────────────────────────────┐
│ Ethernet Frame                  │
│                                 │
│ Destination MAC: BB:BB:BB:...   │
│ Source MAC:      AA:AA:AA:...   │
│                                 │
│        IP Packet                │
│   Src IP: 192.168.1.10          │
│   Dst IP: 192.168.1.20          │
└─────────────────────────────────┘
```

---

# 🔹 Neighbor Table این وسط چه کاره است؟

Linux اطلاعاتی شبیه این را نگه می‌دارد:

```
192.168.1.20 → BB:BB:BB:BB:BB:BB
```

این همان چیزی است که با:

```
ip neigh
```

می‌بینی.

مثلاً:

```
192.168.1.20 dev eth0 lladdr BB:BB:BB:BB:BB:BB REACHABLE
```

یعنی:

> برای رسیدن به `192.168.1.20` از `eth0` استفاده کن و MAC مقصد روی این لینک `BB:BB:BB:BB:BB:BB` است.

---

# 🔥 اما یک نکته خیلی مهم

اگر مقصد **خارج از شبکه محلی** باشد، Linux MAC خودِ مقصد را لازم ندارد.

مثلاً:

```
PC
192.168.1.10
     ↓
Gateway
192.168.1.1
     ↓
Internet
     ↓
8.8.8.8
```

تو می‌خواهی به:

```
8.8.8.8
```

بروی.

Linux می‌فهمد:

```
8.8.8.8
↓
خارج از Subnet من است
↓
باید Packet را به Gateway بدهم
```

پس Ethernet Frame این شکلی می‌شود:

```
Destination MAC = MAC Gateway
Source MAC      = MAC PC

Destination IP = 8.8.8.8
Source IP      = 192.168.1.10
```

یعنی:

> **IP مقصد همچنان 8.8.8.8 است، ولی MAC مقصد، MAC Gateway است.**

---

# 🧩 پس چرا اسمش Neighbor است؟

چون Linux اطلاعات دستگاه‌هایی را که روی **لینک متصل و قابل دسترس مستقیم** هستند، نگه می‌دارد.

مثلاً:

```
PC
 │
 ├── 192.168.1.1 → Gateway
 ├── 192.168.1.20 → PC دیگر
 └── 192.168.1.30 → Printer
```

این‌ها Neighborهای Linux هستند.

اما:

```
8.8.8.8
```

Neighbor مستقیم Linux نیست؛ **Gateway** Neighbor مستقیم است.

## جواب سوال دوم 
اگر لپ‌تاپت با **Wi-Fi** به مودم وصل باشد، باز هم مفهوم **MAC و Frame و Neighbor** وجود دارد؛ فقط به‌جای Ethernet سیمی، از **Wi-Fi (802.11)** استفاده می‌شود.

مثلاً:

```
Laptop
IP: 192.168.1.10
MAC: AA:AA:AA:AA:AA:AA
       │
       │ Wi-Fi
       ↓
Modem/Router
IP: 192.168.1.1
MAC: BB:BB:BB:BB:BB:BB
```

وقتی لپ‌تاپ می‌خواهد با Gateway یعنی `192.168.1.1` ارتباط برقرار کند:

```
192.168.1.1
     ↓
ARP / Neighbor Discovery
     ↓
MAC مودم
BB:BB:BB:BB:BB:BB
     ↓
Wi-Fi Frame
     ↓
مودم
```

پس `ip neigh` همچنان می‌تواند اطلاعاتی مثل این نشان دهد:

```
ip neigh
```

```
192.168.1.1 dev wlan0 lladdr BB:BB:BB:BB:BB:BB REACHABLE
```

یعنی:

- `192.168.1.1` → IP مودم/Gateway
- `wlan0` → کارت Wi-Fi
- `BB:BB:BB:BB:BB:BB` → MAC مربوط به Neighbor
- `REACHABLE` → اخیراً قابل دسترس بوده

### 🔑 نکته اصلی

وقتی گفتیم:

> «برای ارسال Frame باید MAC داشته باشیم»

منظور فقط **Ethernet کابلی** نبود.

در شبکه‌های **Layer 2**، تکنولوژی‌های مختلفی Frame دارند:

```
Ethernet      → کابل
Wi-Fi         → بی‌سیم
```

هر دو با Addressing در لایه لینک کار می‌کنند، ولی **ساختار Frame و نحوه انتقالشان یکسان نیست**.

بنابراین:

```
Cable Ethernet
      ↓
Ethernet Frame

Wi-Fi
      ↓
802.11 Frame
```

ولی در هر دو حالت، Linux برای ارتباط روی لینک محلی باید اطلاعات لازم برای رسیدن به **Next-Hop** را داشته باشد.

### ⭐ و یک نکته جالب

روی لپ‌تاپ Wi-Fi احتمالاً Interface را با چیزی مثل:

```
ip link
```

می‌بینی:

```
wlan0
```

یا در سیستم‌های جدید ممکن است چیزی مثل:

```
wlp2s0
```

باشد.

پس وقتی می‌زنی:

```
ip neigh
```

ممکن است به‌جای `eth0` ببینی:

```
192.168.1.1 dev wlp2s0 ...
```

یعنی:

>ا- **Gateway من از طریق کارت Wi-Fi در دسترس است.**
