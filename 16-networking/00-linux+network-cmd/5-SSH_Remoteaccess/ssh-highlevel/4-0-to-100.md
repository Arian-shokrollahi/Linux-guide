یک **سناریوی واقعی DevOps** را از صفر اجرا کنیم که هر ۴ دستور را در جای درست ببینی:

> ا-`ssh-keygen` → ساخت Key  
> ا-`ssh-copy-id` → انتقال Public Key  
> ا-`ssh-agent` → اجرای Agent  
> ا-`ssh-add` → وارد کردن Private Key به Agent

فرض کنیم لپ‌تاپت **Client** است و یک Linux Server داری:

```
Client
  │
  │ SSH
  ▼
Linux Server
IP: 192.168.1.100
User: deploy
```

---

# 🎯 سناریو

می‌خواهیم از سیستم خودمان به Server وصل شویم، بدون اینکه هر بار Password کاربر `deploy` را وارد کنیم.

## 1. ساخت SSH Key

روی **Client**:

```
ssh-keygen -t ed25519
# Generate an Ed25519 SSH key pair
```

در نتیجه:

```
~/.ssh/
├── id_ed25519       # Private Key 🔐
└── id_ed25519.pub   # Public Key
```

ا-Private Key را نگه می‌داریم و **هرگز به Server کپی نمی‌کنیم**.

---

# 2. کپی Public Key روی Server

```
ssh-copy-id deploy@192.168.1.100
# Install the public key on the server
```

احتمالاً اینجا Password کاربر `deploy` را یک بار می‌خواهد.

پشت صحنه:

```
Client
~/.ssh/id_ed25519.pub
        │
        │ ssh-copy-id
        ▼
Server
~/.ssh/authorized_keys
```

یعنی Public Key ما داخل این فایل Server قرار می‌گیرد:

```
/home/deploy/.ssh/authorized_keys
```

---

# 3. تست SSH Key

حالا:

```
ssh deploy@192.168.1.100
```

اگر Key را بدون Passphrase ساخته باشی، احتمالاً مستقیماً وارد می‌شوی.

اما اگر هنگام `ssh-keygen` برای Private Key یک **Passphrase** گذاشته باشی، SSH ممکن است Passphrase کلید را بخواهد.

اینجاست که `ssh-agent` وارد می‌شود.

---

# 4. اجرای `ssh-agent`

روی Client:

```
eval "$(ssh-agent -s)"
# Start ssh-agent
```

مثلاً:

```
Agent pid 12345
```

حالا Agent در پس‌زمینه اجرا می‌شود.

```
Client
│
├── ~/.ssh/id_ed25519 🔐
│
└── ssh-agent
```

---

# 5. اضافه کردن Private Key به Agent

```
ssh-add ~/.ssh/id_ed25519
# Add private key to ssh-agent
```

اینجا Passphrase کلید را **یک بار** وارد می‌کنی.

بعد Agent کلید را در حافظه نگه می‌دارد.

---

# 6. حالا SSH کنیم

```
ssh deploy@192.168.1.100
```

ا-SSH می‌تواند از Key موجود در Agent استفاده کند.

اگر چند Server داشته باشی:

```
ssh deploy@192.168.1.100
ssh deploy@192.168.1.101
ssh deploy@192.168.1.102
```

لازم نیست هر بار Passphrase کلید را وارد کنی.

---

## 🧠 نقش هر دستور

|Command|وظیفه|
|---|---|
|`ssh-keygen`|ساخت Private/Public Key|
|`ssh-copy-id`|قرار دادن Public Key روی Server|
|`ssh-agent`|نگه‌داری Private Key در حافظه|
|`ssh-add`|اضافه کردن Private Key به Agent|
|`ssh`|اتصال به Server با Key|

### سناریوی واقعی را این‌طور حفظ کن:

```
# 1. Create keys
ssh-keygen -t ed25519

# 2. Install public key on server
ssh-copy-id deploy@192.168.1.100

# 3. Start SSH agent
eval "$(ssh-agent -s)"

# 4. Load private key into agent
ssh-add ~/.ssh/id_ed25519

# 5. Connect
ssh deploy@192.168.1.100
```

**نکته مهم:** `ssh-copy-id` برای **اولین راه‌اندازی دسترسی Key-based** است؛ `ssh-agent` و `ssh-add` برای این هستند که **استفاده از Private Key، مخصوصاً وقتی Passphrase دارد، راحت‌تر شود.**
