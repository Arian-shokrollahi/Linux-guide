## 1. مقدمه `ss`

ا-`ss` مخفف **Socket Statistics** است.

برای مشاهده و بررسی **Socketها و Connectionهای شبکه** در Linux استفاده می‌شود.

مهم‌ترین چیزهایی که با `ss` بررسی می‌کنیم:

- چه Portهایی باز هستند؟
- چه Serviceهایی در حال Listen هستند؟
- چه Connectionهایی برقرارند؟
- کدام Process از یک Port استفاده می‌کند؟
- ا-Connection از چه IP و Portی آمده؟
- وضعیت TCP Connection چیست؟

به‌جای اینکه فقط بگویی:

> «آیا Port 80 باز است؟»

با `ss` می‌توانی بفهمی:

> ا-«Port 80 توسط چه برنامه‌ای و روی چه آدرسی در حال Listen است؟»

---

# 2. ساختار کلی `ss`

ساختار عمومی:

```
ss [OPTIONS] [FILTER]
```

مثلاً:

```
ss -tuln
```

یا:

```
ss -tan
```

---

# 3. Switchهای مهم `ss`

|Switch|معنی|کاربرد|
|---|---|---|
|`-t`|TCP|نمایش Socketهای TCP|
|`-u`|UDP|نمایش Socketهای UDP|
|`-l`|Listening|فقط Portهای در حال Listen|
|`-n`|Numeric|نمایش IP و Port به‌صورت عددی|
|`-a`|All|نمایش همه Socketها|
|`-p`|Process|نمایش Process مربوط به Socket|
|`-4`|IPv4|فقط IPv4|
|`-6`|IPv6|فقط IPv6|
|`-s`|Summary|خلاصه وضعیت Socketها|
|`-r`|Resolve|تلاش برای تبدیل IP به hostname|
|`-o`|Timer|نمایش اطلاعات Timerهای TCP|
|`-i`|Internal TCP|نمایش اطلاعات داخلی TCP|
|`-e`|Extended|نمایش اطلاعات بیشتر|

### ⭐ مهم‌ترین‌ها

اگر بخواهی فقط Switchهای ضروری را یاد بگیری:

```
-t
-u
-l
-n
-a
-p
-4
-6
-s
```

# 3. ترکیب Switchها

قدرت واقعی `ss` زمانی مشخص می‌شود که Switchها را ترکیب کنی.

مثلاً:

```
ss -tuln
```

یعنی:

```
-t → TCP
-u → UDP
-l → Listening
-n → Numeric
```

پس:

> تمام Portهای TCP و UDP که در حال Listen هستند را به صورت عددی نشان بده.

# 4. کاربردهای بسیار مهم

### ① دیدن Portهای Listening

یکی از مهم‌ترین کاربردهای `ss`:

```
ss -tuln
```

مثلاً:

```
Netid  State   Local Address:Port
tcp    LISTEN  0.0.0.0:22
tcp    LISTEN  0.0.0.0:80
udp    UNCONN  0.0.0.0:53
```

می‌فهمی چه Portهایی روی سیستم فعال هستند.

---

### ② فهمیدن اینکه کدام Process از Port استفاده می‌کند

```
ss -tulpn
```

`-p` خیلی مهم است.

مثلاً ممکن است ببینی:

```
users:(("sshd",pid=1234,fd=3))
```

یعنی Port توسط `sshd` استفاده می‌شود.
# وضعیت‌های مهم TCP

وقتی `ss` استفاده می‌کنی، با Stateهای مختلف مواجه می‌شوی:

|State|معنی|
|---|---|
|`LISTEN`|منتظر Connection جدید|
|`ESTABLISHED`|Connection برقرار است|
|`TIME-WAIT`|Connection بسته شده ولی هنوز در وضعیت انتظار است|
|`CLOSE-WAIT`|طرف مقابل Connection را بسته|
|`SYN-SENT`|درخواست اتصال ارسال شده|
|`SYN-RECV`|درخواست اتصال دریافت شده|
|`FIN-WAIT-1`|در حال بستن Connection|
|`FIN-WAIT-2`|منتظر بسته‌شدن طرف مقابل|

برای شروع، این سه تا را **خیلی خوب** یاد بگیر:

```
LISTEN
ESTABLISHED
TIME-WAIT
```

# 5. یک سناریوی واقعی

فرض کن روی Server خودت شک داری که Web Server اجرا شده یا نه.

می‌زنی:

```
ss -tuln
```

می‌بینی:

```
tcp LISTEN 0 128 0.0.0.0:80
```

پس می‌فهمی:

```
TCP
  ↓
Port 80
  ↓
LISTEN
  ↓
روی تمام IPv4 interfaceها
```

حالا می‌خواهی بفهمی **کدام Process** این Port را گرفته:

```
ss -tulpn
```

مثلاً:

```
tcp LISTEN 0 128 0.0.0.0:80
users:(("nginx",pid=1234))
```

حالا می‌دانی:

```
Port 80
   ↓
nginx
   ↓
PID 1234
```

این دقیقاً یکی از کاربردهای مهم `ss` در **Linux Troubleshooting** است.

# جمع‌بندی خیلی کوتاه

```
ss
│
├── بررسی Socket و Connection
│
├── Portهای Listening
│      └── ss -tuln
│
├── Process مربوط به Port
│      └── ss -tulpn
│
├── TCP
│      └── ss -t
│
├── UDP
│      └── ss -u
│
├── IPv4
│      └── ss -4
│
├── IPv6
│      └── ss -6
│
└── خلاصه Socketها
       └── ss -s
```

### ⭐ اگر فقط 5 دستور از `ss` حفظ کنی:

```
ss -tuln
ss -tulpn
ss -tn
ss -uln
ss -s
```

**خلاصه یک‌خطی:**  
`ss` ابزار اصلی Linux برای **دیدن Portها، Connectionها، وضعیت TCP/UDP و Processهای استفاده‌کننده از Socketها** است؛ مهم‌ترین ترکیبش برای شروع هم `ss -tulpn` است
