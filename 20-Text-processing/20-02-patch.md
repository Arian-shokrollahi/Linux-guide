## introducton to patch
## فلسفه دستور patch چیست و چرا درستش کردن؟
- نسخه پایه ای دارید و دارید همه روش کار میکنید⚙ .--->لازمه داشتن نسخه پایه base version. 

- همه از همون شروع کردن سپس یکی میاد یه تغییراتی رویه اون اعمال میکنه که تغییره خوبی است بعد دیکه نمیاد کل فایلو برایه همه بفرسته بلکه میاد اون فایل تغییرات(patch file) رو با diff درست میکنه به این صورت -------------> diff baseversion newversion>patchfile بعد با  redirection operator اون رو میریزید داخل یه فایل که به اون فایل فایل تغییرات یا  patch.file میگوند حاحالا این فایل رو میفرستید برای همکار هاتون نه کله فایل های اون پروژه،فقط فایل تغییرات رو میفرستید.


## مکمل و رفیق صمیمی دستور patch چیست؟
مکمل و رفیق همیشگی دستور patch دستور diff است زیرا :
- 1باید فایل تغییرات رو با دستور diff در فایل دیگری با redirection sign (<< ، >> ، < ، >) بریزیم و سپس
- 2 اینجاست که دستور patch میاد و اون تغییرات رو درون فایلی که میخواید اعمال میکنه

## کجا ها این دستور patch به دردمون میخوره ؟
- 1 ارسال تغییر کوچک به جای کل پروژه : مثلا پروژه -->2گیگ است & اما فایل patch-->چند کیلوبایت
- 2 بررسی تغییرات قبل از قبول کردن آن‌ها
- 3 اعمال تغییرات روی فایل‌های تنظیمات سرور

## پس حالا که فمیدیم patch & diff چیه بریم یه خلاصه بگیم ازشون؟
- دستور `diff` تفاوت‌ها و تغییرات بین دو فایل یا دو نسخه از یک پروژه را پیدا می‌کند.(show delta)
- دستور `patch` آن تغییراتِ کم‌حجم را می‌گیرد و روی فایل‌ها یا پروژهٔ قدیمی اعمال می‌کند؛ بدون اینکه لازم باشد کل فایل یا کل پروژهٔ جدید منتقل شود.
- **1نکته:** دستور diff میاد تفاوت دو فایل رو نشون و اون رو درون فایلی میریزید که میشه patch فایلتون
- **2نکته:** دستور patch میاد اون تغییرات رو اعمال میکنه 
- **3نکته:** پس کار  patch اینه که فایل بزرگ رو دوباره کپی نکنیم و فقط با استفاده از تغیرات کم حجم فایل رو به نسخه جدید تغغیر بدیم

## patch command structure
## ساختار دستور patch:
- 1create patch file with diff-->diff -u baseversion newversion > patchfile
- 2use patch command + patch file-->patch oldv < newv(that file your colleague send.)
