- ا-Signal چیست؟
- ا-Process چطور Signal دریافت می‌کند؟
- تفاوت `SIGTERM` و `SIGKILL`

حتماً. این سه مفهوم دقیقاً به هم مربوط‌اند و برای کار با `htop` و مدیریت Processها خیلی مهم‌اند.

|مفهوم|توضیح ساده|مثال|
|---|---|---|
|**Signal**|یک پیام/دستور از طرف سیستم یا یک Process برای Process دیگر|«لطفاً متوقف شو»|
|**دریافت Signal**|Kernel، Signal را به Process موردنظر می‌رساند و Process بر اساس آن واکنش نشان می‌دهد|Process می‌تواند Signal را handle کند|
|**SIGTERM**|درخواست مؤدبانه برای متوقف شدن Process|`kill PID`|
|**SIGKILL**|دستور اجباری برای پایان فوری Process|`kill -9 PID`|

### 1. ا-Signal چیست؟

در Linux، **Signal** یک پیام بسیار ساده است که Kernel برای اطلاع‌رسانی یا کنترل یک Process استفاده می‌کند.

مثلاً وقتی می‌نویسی:

```
kill 1234
```

در حالت عادی `kill` در واقع **SIGTERM** را برای Process با PID برابر `1234` ارسال می‌کند.

یعنی:

> ا-«Process 1234، لطفاً خودت به شکل صحیح متوقف شو.»

Signalهای معروف:

```
SIGTERM    درخواست خاتمه
SIGKILL    خاتمه اجباری
SIGINT     Interrupt (مثل Ctrl+C)
SIGHUP     Hangup
SIGSTOP    توقف اجباری
SIGCONT    ادامه دادن Process متوقف‌شده
```

---

### 2. Process چطور Signal دریافت می‌کند؟

به‌صورت ساده مسیرش این‌طوریه:

```
User
  ↓
kill / Ctrl+C / system
  ↓
Kernel
  ↓
Signal
  ↓
Process
  ↓
Action
```

مثلاً:

```
kill 1234
```

ا-Kernel بررسی می‌کند که آیا فرستنده اجازه‌ی ارسال Signal به Process شماره `1234` را دارد یا نه.

بعد Signal را به Process می‌رساند.

ا-Process می‌تواند بسته به نوع Signal:

- آن را **handle** کند
- نادیده بگیرد
- رفتار پیش‌فرض Signal را اجرا کند

البته بعضی Signalها استثنا هستند؛ مثلاً **SIGKILL و SIGSTOP قابل catch، block یا ignore کردن نیستند.**

---

### 3. تفاوت `SIGTERM` و `SIGKILL`

این قسمت خیلی مهمه:

|ویژگی|`SIGTERM`|`SIGKILL`|
|---|---|---|
|شماره|`15`|`9`|
|نوع|درخواست خاتمه|خاتمه اجباری|
|Process می‌تواند آن را Handle کند؟|بله|❌ خیر|
|Process می‌تواند نادیده بگیرد؟|بله|❌ خیر|
|امکان Cleanup|بله|معمولاً ❌|
|استفاده‌ی معمول|انتخاب اول|آخرین راه‌حل|

مثلاً:

```
kill 1234
```

معادل:

```
kill -15 1234
```

ولی:

```
kill -9 1234
```

یعنی:

```
SIGKILL → Process را فوراً بکش
```

### چرا اول `SIGTERM`؟

فرض کن یک Process در حال نوشتن اطلاعات روی Disk است.

اگر:

```
kill PID
```

بزنی، Process فرصت دارد کارهای پایانی خودش را انجام دهد؛ مثلاً فایل‌ها را ببندد، connectionها را ببندد و منابعش را آزاد کند.

اما اگر:

```
kill -9 PID
```

بزنی، Kernel Process را **بدون دادن فرصت cleanup** متوقف می‌کند.

بنابراین به‌عنوان Admin معمولاً:

```
SIGTERM
   ↓
اگر Process متوقف نشد
   ↓
SIGKILL
```

را در نظر می‌گیریم.

**نکته‌ی خیلی مهم:** اسم `kill` به این معنی نیست که همیشه Process را فوراً می‌کشد؛ `kill` در اصل ابزاری برای **ارسال Signal** است. دستور `kill PID` به‌طور پیش‌فرض `SIGTERM` می‌فرستد.
