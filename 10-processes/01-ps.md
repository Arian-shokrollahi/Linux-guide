# ps command
---
# اصلاً `ps` چیه؟

ا-`ps` مخفف **Process Status** هست.

کارش اینه که از processهای در حال اجرا روی سیستم **snapshot** بگیره و اطلاعاتشون رو نمایش بده.

یعنی برخلاف `top` که دائماً اطلاعات رو refresh می‌کنه، `ps` در یک لحظه وضعیت processها رو می‌گیره.

مثلاً:

```
ps
```

خروجی ممکنه این باشه:

```
    PID TTY          TIME CMD
   1523 pts/0    00:00:00 bash
   1842 pts/0    00:00:00 ps
```

اینجا:

```
PID   → شماره Process
TTY   → ترمینالی که process به آن متصل است
TIME  → مقدار CPU time مصرف‌شده
CMD   → دستوری که process را اجرا کرده
```

---

# 2. Syntax کلی `ps`

به‌صورت کلی:

```
ps [options]
```

مثلاً:

```
ps aux
```

یا:

```
ps -ef
```

یا:

```
ps -eo pid,ppid,user,stat,cmd
```

نکته‌ی مهم: `ps` چند سبک option دارد.

### سبک UNIX

با `-`:

```
ps -ef
ps -aux
```

### سبک BSD

بدون `-`:

```
ps aux
ps x
```

### سبک GNU

معمولاً `--`:

```
ps --forest
ps --sort=-%cpu
```

پس اگر جایی syntax عجیب دیدی، نترس؛ `ps` تاریخی طولانی دارد و چند syntax را پشتیبانی می‌کند.

---

# 3. مهم‌ترین switchها

## `x`

```
ps x
```

ا-processهای خودت را حتی اگر به terminal متصل نباشند نشان می‌دهد.

مثلاً processهایی که `TTY` آنها `?` است.

---

## `a`

```
ps a
```

ا-processهای مربوط به terminalهای دیگر کاربران را هم در نمایش وارد می‌کند.

---

## `u`

```
ps u
```

اطلاعات را به شکل **user-oriented** نمایش می‌دهد.

مثلاً:

```
USER       PID %CPU %MEM    VSZ   RSS TTY      STAT START   TIME COMMAND
```

بنابراین:

```
ps aux
```

ترکیب بسیار معروفی است.

---

# 4. `ps aux` را دقیق یاد بگیر

این یکی از مهم‌ترین commandهاست:

```
ps aux
```

خروجی:

```
USER       PID %CPU %MEM    VSZ   RSS TTY      STAT START   TIME COMMAND
root         1  0.0  0.1  17000 10000 ?        Ss   10:00   0:02 /sbin/init
arian     1523  2.5  3.2 500000 200000 ?       Sl   10:20   1:20 firefox
```

حالا ستون‌ها:

### `USER`

صاحب process:

```
root
arian
```

---

### `PID`

Process ID:

```
1523
```

این مهم‌ترین شناسه‌ی process است.

مثلاً:

```
kill 1523
```

---

### `%CPU`

درصد CPU مصرفی process.

مثلاً:

```
2.5
```

یعنی process در زمان نمونه‌برداری CPU مصرف می‌کند.

**نکته:** این عدد را با CPU کل سیستم یا یک هسته به‌صورت ساده یکی ندان؛ نحوه‌ی نمایش درصد CPU در `ps` با ابزارهایی مثل `top` تفاوت‌هایی دارد.

---

### `%MEM`

درصد RAM استفاده‌شده توسط process.

مثلاً:

```
3.2
```

---

### `VSZ`

ا-Virtual Memory Size.

مقدار فضای **virtual memory** که process در address space خودش دارد، معمولاً بر حسب KB.

این به معنی «RAM واقعی مصرف‌شده» نیست.

---

### `RSS`

ا-Resident Set Size.

تقریباً مقدار memoryای که از process در **RAM فیزیکی** resident است.

برای بررسی مصرف واقعی RAM، `RSS` معمولاً از `VSZ` معنی‌دارتر است.

---

### `TTY`

ترمینال process.

مثلاً:

```
pts/0
pts/1
?
```

اگر:

```
?
```

دیدی، یعنی process به terminal خاصی متصل نیست.

---

### `STAT`

وضعیت process.

مثلاً:

```
R
S
D
T
Z
```

این بخش خیلی مهمه و بعداً جداگانه باید عمیق یادش بگیری.

---

### `START`

زمان شروع process.

---

### `TIME`

مقدار CPU time مصرف‌شده.

**اشتباه رایج:** این زمان، مدت زمانی که process از ابتدا زنده بوده نیست.

---

### `COMMAND`

دستوری که process را اجرا کرده.

مثلاً:

```
/usr/bin/python3 server.py
```

---

# 5. `ps -ef`

حالت بسیار مهم بعدی:

```
ps -ef
```

مثلاً:

```
UID       PID   PPID  C STIME TTY          TIME CMD
root        1      0  0 10:00 ?        00:00:02 /sbin/init
root      500      1  0 10:01 ?        00:00:00 sshd
arian    1500    500  0 10:10 pts/0    00:00:00 bash
arian    1600   1500  0 10:11 pts/0    00:00:01 python app.py
```

اینجا یک ستون بسیار مهم داریم:

```
PPID
```

یعنی:

ا-**Parent Process ID**

پس:

```
PID 1600
PPID 1500
```

یعنی process شماره `1600` توسط process شماره `1500` ایجاد شده.

در نتیجه:

```
init
 └── sshd
      └── bash
           └── python
```

این رابطه‌ی parent/child برای فهم Linux Processها **خیلی مهم** است.

---

# 6. `ps -e`

```
ps -e
```

تمام processها را انتخاب می‌کند.

مثلاً:

```
ps -e
```

یا:

```
ps -eF
```

---

# 7. `ps -f`

```
ps -f
```

خروجی را به شکل **full-format** می‌دهد.

مثلاً:

```
UID   PID  PPID  C STIME TTY      TIME CMD
```

به همین دلیل:

```
ps -ef
```

خیلی رایج است:

```
-e → همه processها
-f → full format
```

---

# 8. فقط ستون‌هایی که خودت می‌خواهی

این یکی خیلی مهم و حرفه‌ایه:

```
ps -eo pid,ppid,user,stat,%cpu,%mem,cmd
```

مثلاً:

```
PID  PPID USER   STAT %CPU %MEM CMD
1       0 root   Ss    0.0  0.1 /sbin/init
500     1 root   S     0.0  0.2 sshd
1500  500 arian  S     0.1  0.5 bash
1600 1500 arian  R     5.2  1.2 python app.py
```

ساختارش:

```
ps -e o ...
```

یا شکل درست و رایج:

```
ps -eo ...
```

یعنی:

```
-e   → همه processها
-o   → مشخص کن چه ستون‌هایی نمایش داده شوند
```

---

# 9. پرکاربردترین حالت برای CPU

اگر بخواهی ببینی چه processهایی بیشترین CPU را مصرف می‌کنند:

```
ps aux --sort=-%cpu
```

یعنی:

```
--sort   → مرتب‌سازی
-%cpu    → بر اساس CPU، نزولی
```

پس:

```
CPU زیاد
   ↓
process 1
process 2
process 3
...
```

---

# 10. پرکاربردترین حالت برای RAM

```
ps aux --sort=-%mem
```

یعنی processهایی که بیشترین memory را مصرف می‌کنند، اول نمایش داده می‌شوند.

---

# 11. فقط 10 تای اول

مثلاً:

```
ps aux --sort=-%cpu | head
```

یا:

```
ps aux --sort=-%mem | head
```

حتی بهتر:

```
ps aux --sort=-%cpu | head -n 11
```

چرا `11`؟

چون یک خط header داریم + 10 process.

---

# 12. Process Tree

یکی از حالت‌های خیلی مهم:

```
ps aux --forest
```

مثلاً:

```
root
 ├─ systemd
 │   ├─ sshd
 │   │   └─ bash
 │   │       └─ python
 │   └─ cron
 └─ ...
```

این برای فهمیدن parent/child relationship فوق‌العاده است.

---

# 13. پیدا کردن یک Process

مثلاً Firefox:

```
ps aux | grep firefox
```

اما این روش یک مشکل کوچک دارد: خود `grep` هم ممکن است در خروجی دیده شود.

برای همین ابزارهای مناسب‌تر:

```
pgrep firefox
```

یا:

```
pgrep -a firefox
```

---

# 14. دیدن اطلاعات یک PID مشخص

فرض کن PID این است:

```
1523
```

می‌توانی بگویی:

```
ps -p 1523
```

یا با جزئیات بیشتر:

```
ps -fp 1523
```

خیلی کاربردی:

```
ps -p 1523 -o pid,ppid,user,stat,%cpu,%mem,cmd
```

# 15. اگر بخواهی فقط processهای یک User را ببینی

```
ps -u arian
```

یا:

```
ps -fu arian
```

---

# 16. یک ترکیب خیلی کاربردی

اگر بخواهم فقط یک command برای بررسی سریع processها بهت بدهم:

```
ps -eo pid,ppid,user,stat,%cpu,%mem,etime,cmd --sort=-%cpu
```

این بهت می‌دهد:

```
PID
PPID
USER
STAT
CPU
MEM
ELAPSED TIME
COMMAND
```

و بر اساس CPU مرتب می‌کند.

---

# 17. برای تحلیل Process، این ترتیب را حفظ کن

وقتی خروجی `ps` را می‌بینی، این ترتیب را برو:

```
1. PID
      ↓
2. PPID
      ↓
3. USER
      ↓
4. STAT
      ↓
5. %CPU
      ↓
6. %MEM
      ↓
7. RSS / VSZ
      ↓
8. COMMAND
```

مثلاً:

```
PID   PPID USER  STAT %CPU %MEM  RSS   COMMAND
2500  1000 arian R    85.2  4.5  500M  python server.py
```

تحلیل:

- `PID=2500` → شناسه process
- `PPID=1000` → parent آن
- `USER=arian` → متعلق به این user
- `R` → در حال اجرا/runnable
- `%CPU=85.2` → CPU زیادی مصرف می‌کند
- `%MEM=4.5` → حدود 4.5٪ از memory طبق معیار `ps`
- `RSS=500M` → حدود 500 MB resident memory
- `python server.py` → برنامه‌ای که اجرا شده

## ⭐ چیزهایی که واقعاً باید از `ps` بلد باشی

اگر هدفت Linux Administration / Linux Process Management است، این‌ها را **حتماً مسلط شو**:

```
ps
ps x
ps u
ps aux
ps -e
ps -f
ps -ef
ps -p PID
ps -fp PID
ps -u USER
ps -eo ...
ps aux --sort=-%cpu
ps aux --sort=-%mem
ps aux --forest
```

و از همه مهم‌تر مفهوم این‌ها:

```
PID
PPID
USER
TTY
STAT
%CPU
%MEM
VSZ
RSS
TIME
COMMAND
```
