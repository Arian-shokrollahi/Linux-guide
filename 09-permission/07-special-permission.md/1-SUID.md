# SUID
---
### ا-SUID چیست؟

ا-**SUID = Set User ID**

یک **Special Permission** در لینوکس است که بیشتر روی **فایل‌های اجرایی (Executable)** استفاده می‌شود.

وقتی یک فایل اجرایی SUID داشته باشد، برنامه هنگام اجرا به جای اینکه با دسترسی‌های **User اجراکننده** اجرا شود، با دسترسی‌های **Owner فایل** اجرا می‌شود.

مثلاً فرض کن:

```
Owner: root
File:  /usr/bin/example
SUID:  فعال
```

اگر یک کاربر معمولی این برنامه را اجرا کند:

```
./example
```

برنامه با **دسترسی‌های Owner یعنی `root`** اجرا می‌شود، نه با دسترسی‌های معمولی آن کاربر.

---

### شکل SUID در Permission

در Permission معمولی:

```
rwxr-xr-x
```

اگر SUID فعال شود، جای `x` مربوط به **User/Owner**، یک `s` دیده می‌شود:

```
rwsr-xr-x
```

یعنی:

```
User   → rws
Group  → r-x
Others → r-x
```

پس:

```
x → اجرای معمولی
s → اجرای همراه با SUID
```

---

### فعال کردن SUID

به‌صورت عددی:

```
chmod 4755 file
```

عدد **4** در ابتدای `4755` نشان‌دهنده‌ی SUID است.

به‌صورت Symbolic:

```
chmod u+s file
```

---

### پیدا کردن فایل‌های SUID

برای پیدا کردن فایل‌هایی که SUID دارند:

```
find / -perm -4000 2>/dev/null
```

---

### یک نکته خیلی مهم امنیتی ⚠️

ا-SUID مخصوصاً وقتی Owner فایل `root` باشد، **حساس و خطرناک** است؛ چون یک برنامه می‌تواند با سطح دسترسی بالاتر از کاربری که آن را اجرا کرده کار کند.

پس برای امتحان این جمله را حفظ کن:

> ا-**SUID باعث می‌شود یک فایل اجرایی با Permissionهای Owner خودش اجرا شود، نه Permissionهای کاربری که آن را اجرا کرده است.**

مثلاً:

```
Owner = root
SUID = فعال
User = ali

ali → اجرای برنامه → برنامه با Permissionهای root اجرا می‌شود
```
