این دوتا خیلی راحت با هم قاطی می‌شن، چون هر دو برای **pattern matching** استفاده می‌شن؛ ولی کاربرد و syntax متفاوتی دارن.

## تفاوت اصلی در یک جمله

> ا-**Wildcard/Glob برای پیدا کردن اسم فایل‌ها و مسیرها در Shell است، ولی Regex برای پیدا کردن و پردازش الگوهای داخل متن است.**

### 1. Wildcard / Glob

بیشتر توسط **Shell** مثل Bash استفاده می‌شود.

مثلاً:

```
ls *.log
```

یعنی:

> فایل‌هایی که هر اسمی دارند ولی با `.log` تمام می‌شوند.

چند wildcard مهم:

|Wildcard|معنی|
|---|---|
|`*`|هر تعداد کاراکتر|
|`?`|دقیقاً یک کاراکتر|
|`[abc]`|یکی از `a` یا `b` یا `c`|
|`[0-9]`|یکی از اعداد 0 تا 9|

مثلاً:

```
ls *.txt
```

فایل‌های:

```
a.txt
hello.txt
server.log.txt
```

را match می‌کند.

---

# 2. Regular Expression

ا-Regex معمولاً برای **متن** استفاده می‌شود.

مثلاً با `grep`:

```
grep '^error' logfile
```

یعنی:

> خط‌هایی را پیدا کن که با `error` شروع می‌شوند.

اینجا `^` یک مفهوم Regex است و معنی‌اش **شروع خط** است.

ا-Regex امکانات خیلی بیشتری برای توصیف متن دارد:

```
^error.*[0-9]+$
```

می‌توانی مشخص کنی:

- از کجا شروع شود
- چه کاراکترهایی داشته باشد
- چند بار تکرار شوند
- چه گزینه‌هایی قابل قبول باشند
- کجا تمام شود
- قسمت‌هایی از pattern را group کنی

# تفاوت `*` خیلی مهم است

یکی از بهترین راه‌ها برای فهم تفاوت همین `*` است.

در **Wildcard**:

```
*.log
```

یعنی:

> هر چیزی قبل از `.log`

اما در **Regex**:

```
.*\.log
```

تقریباً یعنی:

> هر تعداد کاراکتر، سپس `.log`

پس `*` در این دو یکی نیست.

### Wildcard:

```
*
```

= هر تعداد کاراکتر

### Regex:

```
*
```

= **تکرار صفر یا بیشترِ چیزی که قبل از آن آمده**

مثلاً:

```
a*
```

یعنی:

```
""
"a"
"aa"
"aaa"
"aaaa"
...
```

ولی به‌تنهایی `*` معنی «هر چیزی» نمی‌دهد.

برای «هر چیزی» در Regex معمولاً می‌بینی:

```
.*
```

# یک مثال خیلی خوب

فرض کن این فایل‌ها را داری:

```
server.log
error.log
access.log
server.txt
error.txt
```

### با Wildcard

```
ls *.log
```

می‌گویی:

> فایل‌هایی که اسمشان با هر چیزی شروع می‌شود و با `.log` تمام می‌شود.

نتیجه:

```
server.log
error.log
access.log
```

اما اگر داخل یک log بخواهی خطوطی را پیدا کنی که مثلاً با `ERROR` شروع می‌شوند:

```
grep '^ERROR' server.log
```

اینجا دیگر داری با **Regex** کار می‌کنی.

# یک تفاوت مفهومی خیلی مهم

به این شکل در ذهنت نگه دار:

```
              Pattern Matching
                     │
          ┌──────────┴──────────┐
          │                     │
       Wildcard                Regex
          │                     │
          ▼                     ▼
      File names              Text
      Paths                   Logs
                              Configs
                              Command output
                              Data
```

### ا-Wildcard بیشتر می‌گوید:

> **کدام فایل/مسیر؟**

مثلاً:

```
*.conf
```

### ا-Regex بیشتر می‌گوید:

> **چه الگویی داخل این متن وجود دارد؟**

مثلاً:

```
^server[0-9]+
```

## برای مسیر یادگیری تو

چون داری Linux را جدی و از پایه یاد می‌گیری، ترتیب ذهنی خوب این است:

```
Shell
 │
 ├── Quoting
 ├── Wildcards / Globbing
 │      ├── *
 │      ├── ?
 │      ├── [...]
 │      └── brace expansion
 │
 └── Text Processing
        │
        └── Regular Expression
               ├── grep
               ├── sed
               └── awk
```

ا-**Wildcard را برای Shell/File matching یاد بگیر؛ Regex را برای Text matching و text processing.**

و یک نکته مهم: `find` هم patternهایی شبیه wildcard دارد، ولی آن‌ها را نباید با Regex یکی بگیری؛ `find -name '*.log'` با `grep -E '.*\.log'` از نظر syntax و موتور matching یک چیز نیستند.ی
