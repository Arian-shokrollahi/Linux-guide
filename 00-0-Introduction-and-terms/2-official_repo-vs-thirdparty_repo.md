# ا-1. Official Repository چیست؟

ا-**Official Repository** یا **مخزن رسمی**، مخزنی است که توسط خود تیم توسعه‌دهنده‌ی یک توزیع Linux ایجاد و مدیریت می‌شود.

مثلاً در Ubuntu، Repository های رسمی توسط تیم Ubuntu و Canonical نگهداری می‌شوند.

هدف آن‌ها ارائه‌ی Package هایی است که:

- تست شده‌اند.
- با نسخه‌ی سیستم سازگار هستند.
- از نظر امنیتی بررسی شده‌اند.

مثال:

در Ubuntu:

```
sudo apt install nginx
```

ا-`apt` از Repository رسمی Ubuntu، Package مربوط به nginx را دریافت می‌کند.

---

# ا-2. Third-Party Repository چیست؟

ا-**Third-Party Repository** یعنی مخزنی که توسط یک شرکت، سازمان یا فردی خارج از تیم اصلی توزیع Linux ساخته و مدیریت می‌شود.

یعنی:

```
Ubuntu
   ❌ ایجاد نکرده

شرکت یا Developer دیگر
   ✅ ایجاد کرده
```

معمولاً برای زمانی استفاده می‌شود که:

- نرم‌افزار در Repository رسمی وجود ندارد.
- نسخه‌ی جدیدتری از یک نرم‌افزار لازم داریم.
- نرم‌افزار خاصی نیاز داریم.

مثلاً یک شرکت ممکن است Repository خودش را برای نصب آخرین نسخه‌ی یک برنامه ارائه دهد.

---

# جدول مقایسه Official Repository و Third-Party Repository

|ویژگی|Official Repository|Third-Party Repository|
|---|---|---|
|تعریف|مخزن رسمی توزیع Linux|مخزن ساخته شده توسط شخص یا شرکت دیگر|
|مدیریت‌کننده|تیم رسمی توزیع|Developer یا سازمان خارجی|
|مثال|Ubuntu Repository|Repository شرکت‌ها یا پروژه‌های مستقل|
|امنیت|معمولاً بالاتر|بستگی به سازنده دارد|
|تست شدن Package ها|معمولاً تست شده‌اند|ممکن است کمتر تست شده باشند|
|سازگاری با سیستم|معمولاً بسیار خوب|ممکن است مشکل سازگاری داشته باشد|
|تعداد Package|محدود به سیاست توزیع|ممکن است Package های خاص بیشتری داشته باشد|
|نسخه نرم‌افزار|معمولاً پایدار ولی گاهی قدیمی‌تر|معمولاً جدیدتر|
|اعتماد|اعتماد بیشتر|نیاز به بررسی منبع دارد|
|استفاده پیشنهادی|انتخاب اول|فقط در صورت نیاز|

# توضیحات تکمیلی

## 1. چرا Official Repository امن‌تر است؟

چون Package ها معمولاً:

- بررسی می‌شوند.
- توسط Maintainer های رسمی نگهداری می‌شوند.
- با سیستم تست می‌شوند.

مثلاً وقتی نصب می‌کنی:

```
sudo apt install vim
```

احتمال اینکه Package مشکل جدی ایجاد کند کمتر است.

---

## 2. چرا از Third-Party Repository استفاده کنیم؟

گاهی Repository رسمی چیزی که می‌خواهیم را ندارد.

مثلاً:

نسخه موجود:

```
Python 3.10
```

ولی پروژه ما نیاز دارد:

```
Python 3.12
```

ممکن است از یک Repository خارجی استفاده کنیم.

---

## 3. خطر Third-Party Repository چیست؟

چون کنترل اصلی دست توزیع Linux نیست.

اگر Repository نامعتبر باشد ممکن است:

- ا-Package مخرب باشد.
- ا-Dependency مشکل ایجاد کند.
- سیستم ناپایدار شود.

پس نباید هر Repository ای را اضافه کنیم.

---

## 4. قانون مهم در Linux Administration

ترتیب پیشنهادی:

```
اول:
Official Repository

اگر نبود:
Third-Party Repository معتبر
```

# خلاصه نهایی

```
Official Repository
=
مخزن رسمی Linux Distribution
=
امن‌تر، تست‌شده‌تر، سازگارتر


Third-Party Repository
=
مخزن خارجی
=
Package های بیشتر یا جدیدتر
ولی نیازمند اعتماد و بررسی
```

در مدیریت حرفه‌ای Linux همیشه اول از **Official Repository** استفاده می‌کنیم و فقط زمانی سراغ **Third-Party Repository** می‌رویم که دلیل مشخصی داشته باشیم.
